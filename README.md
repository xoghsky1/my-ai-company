# 도메인 분석 · 기능 제안 포트폴리오

내부 툴 서비스 기획 경험에 **외부 도메인 이해**를 더하기 위한 저장소입니다.
관심 도메인의 프로덕트를 조사·분석하고, 개선 기능을 제안한 문서를 모아 PM·서비스 기획 포트폴리오로 활용합니다.

## 원칙
- 결과물은 **PM·서비스 기획 수준**의 Markdown 문서입니다. 개발 코드와 디자인 시안은 다루지 않습니다.
- 공개된 자료(공식 사이트, 기사, IR, 앱스토어 리뷰 등)를 근거로 하고, **출처를 반드시 남깁니다.**
- 조사·초안은 Claude가 돕고, **문제 선정과 최종 판단은 직접** 합니다. 면접에서 설명할 수 있는 문서만 남깁니다.
- 제안서는 실제 출시 성과가 아니므로 **"개인 분석 프로젝트"로 명시**하고, 성과는 **기대 지표(가설)** 로 표현합니다.
- 개인정보(연락처 등)와 사내 기밀은 저장소에 넣지 않습니다.

## 작업 흐름
| 단계 | 문서 | 내용 |
|---|---|---|
| 1 | `00_도메인_개요.md` | 시장 구조, 비즈니스 모델, 주요 플레이어, 핵심 지표 |
| 2 | `01_프로덕트_분석.md` | 타깃 사용자, 핵심 기능, 사용자 여정, 리뷰·불만 패턴, 직접 사용 메모 |
| 3 | `02_문제_발견.md` | 개선 기회 후보 3~5개 → 하나 선택(선정 이유 기록) |
| 4 | `03_기능_제안서.md` | 포트폴리오에 들어가는 최종본 |
