# 헬스케어 도메인 개요

> 작성일: 2026-10-02
> 조사 방식: 웹 검색 결과 요약 기준. 뉴스 본문은 접근이 막혀 **원문을 직접 읽지 못했습니다.**
> 표기: ✅ 복수 출처에서 확인 / ⚠️ 단일 출처·요약만 확인 → 포트폴리오에 쓰기 전 원문 확인 필요 / ❓ 확인 못 함

## 1. 한눈에 보기

- **도메인 정의:** 개인의 건강 관리, 병원 탐색·예약, 진료, 의료 데이터 활용을 디지털로 연결하는 서비스. 크게 **환자·일반 사용자 대상(B2C)** 과 **병원·의원 업무 대상(B2B)** 으로 나뉩니다.
- **네이버의 위치:** 검색·예약·결제 같은 일상 플랫폼 접점(B2C)과, 의원용 EMR(전자의무기록, B2B)을 함께 갖추려는 움직임이 뚜렷합니다. ✅
- **핵심 이슈 3가지**
  1. 흩어진 건강 기능(증상 확인·병원 예약·걸음 수·복약)을 한곳으로 모으는 **통합 진입점 경쟁** ✅
  2. 의료 AI 사업화: 진료 데이터와 검색을 결합한 AI 서비스 ⚠️
  3. 개인 의료정보를 다루는 **규제·동의·보안** 제약 ✅

## 2. 네이버 헬스케어 현황 (이 저장소의 분석 대상)

| 구분 | 내용 | 확인 |
|---|---|---|
| 조직 | 2026-10-01 테크 비즈니스 부문 산하에 헬스케어 조직 신설. 세나클 공동대표(위의석·박찬희)가 공동대표를 맡음 | ⚠️ |
| B2C 서비스 | '네이버 헬스케어': 증상체크(진료과·병원 안내), 만보기, 복약관리, 건강정보, 병원 예약. 흩어진 기능을 모은 **'헬스케어 홈'** | ✅ |
| 증상체크 | 아픈 부위·증상을 입력하면 예상 병명과 가까운 진료 병원을 안내. 네이버 예약과 연동되어 바로 예약 가능 | ✅ |
| B2B 서비스 | 세나클의 클라우드 EMR **'오름차트'**: 의원급 대상, 예약·접수·진료비 청구·처방·환자관리 지원 | ✅ |
| 결제 연동 | 오름차트와 'Npay 커넥트' 연동(병원 내 디지털 결제) | ⚠️ |
| 투자·인수 | 세나클 인수(최대주주), 인바디 지분 8.5% 투자, 제이앤피메디(임상시험 데이터) 투자 | ⚠️ |
| 의료 AI | 하이퍼클로바X로 건강검진 결과 기반 소견서 작성 등을 사내 병원에서 테스트 중 | ⚠️ |
| 사내 의료 | 네이버 부속의원이 오름차트로 진료. 네이버 예약 기반 사전 문진·건강 리포트 제공 | ⚠️ |

**해석(내 판단 필요):** 네이버는 B2C 쪽에서 *"아프면 일단 검색·예약"* 접점을, B2B 쪽에서 *병원 내부 데이터(EMR)* 를 확보하는 구조로 보입니다. 두 쪽을 이어 주는 지점(예: 예약 → 사전 문진 → 진료 → 사후 관리)이 제안 기회가 될 수 있습니다.

## 3. 이해관계자

| 주체 | 역할 | 원하는 것 | 불편한 점(가설) |
|---|---|---|---|
| 일반 사용자·환자 | 증상 확인, 병원 선택, 예약, 건강 관리 | 빠른 병원 탐색, 대기 감소, 내 기록의 연속성 | 증상 정보가 어디까지 신뢰되는지 불명확, 병원마다 기록이 따로 있음 |
| 의원(1차 의료기관) | 진료, 접수, 청구 | 업무 자동화, 환자 유입, 노쇼 감소 | 접수·청구·예약이 여러 도구로 분산 |
| 의료진 | 진료·기록 | 기록 부담 감소, 환자 정보 파악 | 문진·차트 작성 시간 |
| 플랫폼(네이버 등) | 접점·데이터·인프라 | 이용자 확보, 의료 데이터 활용 | 규제와 의료계 반발 |
| 규제기관 | 개인정보·의료법 | 안전한 데이터 활용 | — |

## 5. 비즈니스 모델 (가설)

- **B2C(네이버 헬스케어):** 직접 과금보다 체류·검색·예약 트래픽 확대와 데이터 접점 확보가 목적으로 보임 ⚠️
- **B2B(오름차트):** 의원 대상 SaaS(구독) + 결제·청구 연동 ⚠️
- **전략:** 데이터 확보 → AI 모델 개발 → 사업화로 이어지는 **전 밸류체인 내재화** 방향 ⚠️

## 6. 규제·제약

- **의료 마이데이터:** 개인정보보호위원회 주도로 만성질환 관리, 복약 관리 등 분야에서 순차 시행 ⚠️
- **비대면진료:** 규제 샌드박스에서 비대면진료 시 환자 건강정보 활용을 플랫폼에 처음 허용한 사례 있음 ⚠️
- **의료계 반발:** 환자 동의·전송요구권 기반의 '디지털 헬스케어법'에 의료계가 반대 ⚠️
- **개인정보 보호:** 플랫폼의 환자 정보 관리 우려, 암호화 등 보안 관리 개선 요구 사례 ⚠️
- **기획 시사점:** 민감정보(건강정보)는 **동의·열람 권한·보관 범위 설계**가 기능 자체만큼 중요함 → 이력서의 *접근 정책 설계* 경험과 연결 가능

## 7. 핵심 지표 (후보)

| 지표 | 정의 | 왜 중요한가 |
|---|---|---|
| 증상체크 → 예약 전환율 | 증상체크 사용자 중 병원 예약까지 완료한 비율 | 정보 서비스가 실제 행동으로 이어지는지 |
| 예약 노쇼율 | 예약 후 미방문 비율 | 병원 가치와 사용자 신뢰의 지표 |
| 재방문·주간 활성 | 건강 기능 재사용 빈도 | 일상 접점으로 자리 잡았는지 |
| 기록 연동률 | 병원 기록이 개인 건강 기록으로 이어진 비율 | B2B·B2C 연결 효과 |

> 위 지표는 도메인 이해를 위한 후보이며, 네이버가 공개한 지표가 아닙니다.
