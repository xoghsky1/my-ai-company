## 1. 문제 후보

| # | 문제 | 영향 사용자 | 근거 | 내 경험과의 연결 |
|---|---|---|---|---|
| A | **쓸 이유가 약하다.** 개별 기능이 다른 앱과 겹쳐, 네이버 헬스케어만의 대표 가치가 보이지 않음 | 신규·이탈 가능 사용자 | 👤 | 문제 정의, 기능 우선순위 (표준화·통합 플랫폼 경험) |
| B | **가족 건강 관리가 안 된다.** 가족의 기록·처방을 한곳에서 관리할 수 없음 | 부모·자녀를 챙기는 사용자 | 👤 (가족 기능 부재는 ❓ 추가 확인) | 권한·접근 정책 설계(법인별 접근 정책) |
| C | **외부 기기·앱 데이터가 연결되지 않는다.** 가정용 체중계 등 이미 쓰는 기기 데이터를 가져오지 못함 | 기기 보유 사용자 | 👤 | 외부 데이터 연동, 데이터 표준화 |
| D | **기록이 행동으로 이어지지 않는다.** 만보기·복약 기록이 쌓여도 예약·복약 지속으로 연결되는 장치가 없음 | 만성질환·복약 사용자 | 👤 | 데이터 기반 개선, 자동화 흐름 설계 |
| E | **헬스 미션의 내세울 가치가 불명확할 수 있다.** 보상 중심이면 보상이 끝나면 이탈 | 신규 유입 사용자 | 👤 (공개 정보 ❓) | KPI·가설 설정, 단계별 범위 |

## 2. 후보 간 관계
B·C·D는 하나로 이어집니다: **가족과 기기의 데이터를 모으고(B·C) → 예약·복약 행동으로 연결(D)** 하면 A(쓸 이유)의 답이 되고, E(미션)는 그 위에 얹는 유입 장치가 될 수 있습니다.

## 3. 선정 기준 (제안)
1. 사용자 영향도 — 실제 쓰는 이유를 만드는가
2. 근거의 확실성 — 공개 자료·직접 사용으로 뒷받침되는가
3. 네이버만의 강점 활용 — 예약·결제·인바디·세나클을 쓸 수 있는가
4. 내 경험과의 연결 — 면접에서 깊이 있게 설명 가능한가
