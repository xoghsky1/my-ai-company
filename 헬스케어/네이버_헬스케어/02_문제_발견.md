# 네이버 헬스케어 문제 발견

> 근거 표기: 👤 직접 사용 / ✅·⚠️ 공개 자료 (01_프로덕트_분석 참고)

## 1. 문제 후보

| # | 문제 | 영향 사용자 | 근거 | 내 경험과의 연결 |
|---|---|---|---|---|
| A | **쓸 이유가 약하다.** 개별 기능이 다른 앱과 겹쳐, 네이버 헬스케어만의 대표 가치가 보이지 않음 | 신규·이탈 가능 사용자 | 👤 | 문제 정의, 기능 우선순위 (표준화·통합 플랫폼 경험) |
| B | **가족 건강 관리가 안 된다.** 가족의 기록·처방을 한곳에서 관리할 수 없음 | 부모·자녀를 챙기는 사용자 | 👤 (가족 기능 부재는 ❓ 추가 확인) | 권한·접근 정책 설계(법인별 접근 정책) |
| C | **외부 기기·앱 데이터가 연결되지 않는다.** 가정용 체중계 등 이미 쓰는 기기 데이터를 가져오지 못함 | 기기 보유 사용자 | 👤 | 외부 데이터 연동, 데이터 표준화 |
| D | **기록이 행동으로 이어지지 않는다.** 만보기·복약 기록이 쌓여도 예약·복약 지속으로 연결되는 장치가 없음 | 만성질환·복약 사용자 | 👤 | 데이터 기반 개선, 자동화 흐름 설계 |
| F | **처방 이력이 남지 않는다.** 진료 결과와 처방 약이 자동으로 기록되지 않아 "그때 무슨 약을 먹었는지"를 알 수 없고, 약 봉투 촬영이라는 수동 단계가 필요 | 병원을 자주 가는 사용자, 만성질환·가족 돌봄 사용자 | 👤 + ✅ (약 등록이 촬영 방식) | 데이터 연동·자동화 흐름, 사용자 행동 데이터 |
| G | **증상체크가 일상 표현을 못 알아듣는다.** "항문" 같은 말을 입력하면 검색되지 않아, 사용자가 의학 용어로 바꿔 입력해야 함 | 증상체크 신규·일반 사용자 | 👤 (실패 사례 추가 수집 필요) | **자연어 검색 도입으로 상세 진입률 21% → 36%** 개선 경험 |
| E | **헬스 미션의 내세울 가치가 불명확할 수 있다.** 보상 중심이면 보상이 끝나면 이탈 | 신규 유입 사용자 | 👤 (공개 정보 ❓) | KPI·가설 설정, 단계별 범위 |

## 2. 후보 간 관계
B·C·D·F는 하나로 이어집니다: **가족·기기·진료 결과의 데이터를 자동으로 모으고(B·C·F) → 예약·복약 행동으로 연결(D)** 하면 A(쓸 이유)의 답이 되고, E(미션)는 그 위에 얹는 유입 장치가 될 수 있습니다.

G는 독립적으로도 완결되는 **작은 범위의 제안**입니다. 이력서의 자연어 검색 성과(21% → 36%)와 가장 직접 연결되지만, 단독으로는 기능 하나의 개선에 그칠 수 있습니다.

### 경쟁 서비스와의 관계 (F의 위험 요인)
- 정부 '나의 건강기록' 앱과 '나만의닥터'는 이미 의료마이데이터로 **처방 내역 조회**를 제공합니다 ⚠️. 따라서 F의 차별점은 "조회"가 아니라 **"딸깍 자동 등록 + 복약 알림 + 네이버 예약 연계"** 에 있어야 합니다.
- 반대로 네이버는 **예약·결제·검색이 한 계정에 있다**는 점이 이들에게 없는 강점입니다.

## 3. 선정 기준 (제안)
1. 사용자 영향도 — 실제 쓰는 이유를 만드는가
2. 근거의 확실성 — 공개 자료·직접 사용으로 뒷받침되는가
3. 네이버만의 강점 활용 — 예약·결제·인바디·세나클을 쓸 수 있는가
4. 내 경험과의 연결 — 면접에서 깊이 있게 설명 가능한가
5. 경쟁 대비 차별성 — 이미 있는 서비스와 어떻게 다른가
